# Changelog

- 2026-08-08: One Subject is admitted to one participant at a time, across checkouts and beside a manual `forest run`. Before the expensive work starts, `claimAdmission` publishes a compare-and-set git fact at `refs/forest/claim/<subject>` (so a fresh clone observes it) and guards it with a host-local flock. A competitor on the same host refuses with a named `admission refused` error, so `forest serve` and `forest run` never duplicate one Subject's agent run; a competitor on a different host refuses too, because a foreign holder's liveness is not observable. Recovery needs no timeout: a holder is alive iff its lock file is still flocked, and a hard-killed participant's flock is dropped by the OS, so a later pass reclaims the abandoned claim without operator action. The release removes the claim by compare-and-set on the ref it observed, so a stale release never erases a later holder.
- 2026-08-08: Credential-shaped text is redacted before publication and a run that would publish it is recorded as blocked (#120). Agent-authored prose is shipped verbatim into three outbound channels — the pull-request body (`flow_builder.go`), the comments that mirror verdict notes and check output (`projection.go`), and the notes pushed to the remote (`notes.go`). Every channel now passes through one `redactSecretShaped` scrub that replaces vendor key prefixes (`sk-...`, GitHub, Stripe, Slack, AWS), the Mint marker shape (`__mint.<alias>__`), and the factory's own `.ts.net` proxy host with `[REDACTED]` before anything leaves. The Builder additionally refuses the whole run — no branch pushed, no pull request opened — and records status `blocked` when a forced `report.json` carries credential-shaped prose, so a pull request containing a secret never reaches the host and an operator is signalled. Benign text round-trips unchanged.
- 2026-08-08: The host config is gated against check injection (#119). A run executes only inside a linked worktree, so any working-tree change to the factory's own `forest.yaml` would be a command installed out of band that the next pass executes on the host through `sh -c`. Every flow now refuses to act while `forest.yaml` differs from the committed revision (`verifyHostConfig`, checked at the top of each pass in `runFlowLoop` and in `runOnce`), and the refusal names the file. The one legitimate channel for changing what the runner executes is a committed change that lands through independent review and merge; an uncommitted (staged or unstaged) working-tree write stops every pass. Existing scrubbed-`PATH`/`FOREST_CHECK_PATH` check-environment isolation is unchanged.
- 2026-08-08: Every agent run now carries a wall-clock deadline. `deadline_seconds` is required and must be positive in each agent's `agent.yaml` (`loadAgent` refuses a missing or zero value, so a run can never be unbounded in time). The harness cancels a run that exceeds its lane's declared bound, records it as a mechanical `timeout_failed` — never a content rejection — with the elapsed time and last trace event, and releases its lane. The recorded failure names where the run stopped so an operator can see the stall, and the lane accepts new work on the next pass.
- 2026-08-07: A Checks note is written only when the declared checks actually ran. `runChecks` builds the note's status from the observed result instead of assuming `pass`, and a preflight failure (check environment, missing toolchain, unresolvable `FOREST_CHECK_PATH`) writes no note and is classified as a mechanical `checks_environment_failed` failure for an operator. The Verifier no longer clears a real check error merely because a note already exists on the Revision, so a Revision whose checks never executed once can no longer be reviewed and merged.
- 2026-08-07: Per-run factory artifacts no longer enter a managed repository's working tree. `renderMarkdown` and opencode's materialised `node_modules` move from the worktree's `.opencode/` into a per-run config root outside it, and opencode is pointed at that root with `XDG_CONFIG_HOME` set in the child environment. The provider configuration a real run actually uses (the factory project's own `.opencode/opencode.json`, falling back to the operator's global opencode config) is preserved there. Local project-config discovery is disabled for the managed worktree (`OPENCODE_DISABLE_PROJECT_CONFIG`), so a `.opencode/opencode.json` a repository ships is neither read nor written. A managed repository now needs no `.gitignore`, no filesystem-scanner exclusion, and no hook change to be worked by the factory, opencode installs its provider packages in the run root rather than the worktree, and `git add -A` can never stage the rendered declaration. The external-config harness is tested against opencode's real config/agent interface, including a worktree that already carries its own project config.
- 2026-08-07: Item identity is now an opaque string end to end. `Subject.ID` and ledger rows carry the tracker's native id ("69" for GitHub, a Habitat id for another source); branches keep the `forest/<id>-<slug>` shape and the reverse lookup no longer assumes the id is an integer. Because the branch delimiter is the first `-`, an id that itself contains `-` is escaped (id `-` becomes `%2D`, `%` becomes `%25`) so any id round-trips; numeric and hyphen-free ids are unchanged. The ledger's `issue` field becomes a string: the loader tolerates the old integer shape so existing rows stay readable (clean cutover; old rows are accepted, new rows are written as opaque strings). Merge behavior, brake refs, and worktree naming are unchanged for numeric GitHub ids.
- 2026-08-06: Replaced the pull-request state machine, label-as-state ownership, and cost accounting. Three independent Flows coordinate through repository state, while Verdicts and checks are stored as git notes. The Builder publishes unreviewed branches; the Verifier reviews and merges them on its own clock.
