# Changelog


- 2026-08-08: Merge retirement is resumable across process stops (#222). Host mode first publishes `preparing`, upgrades it to `pending` after durable approval, advances an exact merged fact to `observed` before approval-note read, and lands it after approval and passing Checks. Native merges publish `landed` atomically with `master`. A note-read failure after an exact merge retains `observed`, and no-view responses retain the current fact. These facts block duplicate Builder work until Tracker cleanup completes.
- 2026-08-08: Agent declarations now own commit authorship. Every `agent.yaml` requires `commit.name` and `commit.email`; Builder and Fixer commits use their acting agent, Verifier rebases preserve authors with a declared Verifier committer, and native squash commits use the Verifier. `forest agents` prints the author. The global `forest.yaml` identity is removed. Host pull requests, pushes, and Host-created merge commits keep the authenticated Host attribution.
- 2026-08-08: All local fetches and updates of durable notes share one checkout lock (#227). Concurrent Flow selectors and writers now reconcile Verdict and Checks refs without local ref-lock failures or lost remote facts. A note rejected by the remote is removed locally before another reader can mistake it for a durable fact. Writers reconcile the remote ref before adding a redacted note, so local-only note text can never cross the publication boundary. Durable blob-ref readers fetch objects without creating shared local refs.
- 2026-08-08: Admission coordinates one canonical Subject across checkouts and manual runs with a per-owner lock and a durable compare-and-set claim (#192). The Manager binds each Effect to the selected candidate-set Revision. It rechecks current Item Revision and durable coverage under Item admission immediately before a tag Effect.
- 2026-08-08: Self-update canonicalizes source aliases, removes interrupted builds, installs only a smoke-tested binary while every Flow is idle, records the update, and exits for supervisor restart. It never replaces a live signal handler with `exec`. A second signal kills managed commands, exits without waiting for repository I/O, and leaves linked-worktree cleanup to the next startup.
- 2026-08-08: Credential-shaped text is redacted before publication and a run that would publish it is recorded as blocked (#120). The pull-request body, projected comments, durable notes, and shared Git commit-message sink pass through `redactSecretShaped`. It replaces vendor key prefixes (`sk-...`, GitHub, Stripe, Slack, AWS), Mint markers, and the factory proxy host with `[REDACTED]`. The Builder additionally refuses a run when forced report prose is credential-shaped, so no branch or Projection carries that report.
- 2026-08-08: The host config is gated against check injection (#119). A run executes only inside a linked worktree, so any working-tree change to the factory's own `forest.yaml` would be a command installed out of band that the next pass executes on the host through `sh -c`. Every flow now refuses to act while `forest.yaml` differs from the committed revision (`verifyHostConfig`, checked at the top of each pass in `runFlowLoop` and in `runOnce`), and the refusal names the file. The one legitimate channel for changing what the runner executes is a committed change that lands through independent review and merge; an uncommitted (staged or unstaged) working-tree write stops every pass. Existing scrubbed-`PATH`/`FOREST_CHECK_PATH` check-environment isolation is unchanged.
- 2026-08-08: Every agent run now carries a wall-clock deadline. `deadline_seconds` is required and must be positive in each agent's `agent.yaml` (`loadAgent` refuses a missing or zero value, so a run can never be unbounded in time). The harness cancels a run that exceeds its lane's declared bound, records it as a mechanical `timeout_failed` — never a content rejection — with the elapsed time and last trace event, and releases its lane. The recorded failure names where the run stopped so an operator can see the stall, and the lane accepts new work on the next pass.
- 2026-08-07: A Checks note is written only when the declared checks actually ran. `runChecks` builds the note's status from the observed result instead of assuming `pass`, and a check-environment construction failure writes no note and is classified as a mechanical `checks_environment_failed` failure for an operator. A command that starts writes a Checks note with its observed result, including a missing executable reported by the shell. The Verifier no longer clears a real check error merely because a note already exists on the Revision, so a Revision whose checks never executed once can no longer be reviewed and merged.
- 2026-08-07: Per-run factory artifacts no longer enter a managed repository's working tree. `renderMarkdown` and opencode's materialised `node_modules` move from the worktree's `.opencode/` into a per-run config root outside it, and opencode is pointed at that root with `XDG_CONFIG_HOME` set in the child environment. The provider configuration a real run actually uses (the factory project's own `.opencode/opencode.json`, falling back to the operator's global opencode config) is preserved there. Local project-config discovery is disabled for the managed worktree (`OPENCODE_DISABLE_PROJECT_CONFIG`), so a `.opencode/opencode.json` a repository ships is neither read nor written. A managed repository now needs no `.gitignore`, no filesystem-scanner exclusion, and no hook change to be worked by the factory, opencode installs its provider packages in the run root rather than the worktree, and `git add -A` can never stage the rendered declaration. The external-config harness is tested against opencode's real config/agent interface, including a worktree that already carries its own project config.
- 2026-08-07: Item identity is now an opaque string end to end. `Subject.ID` and ledger rows carry the Tracker's native id. Branch encoding preserves `[A-Za-z0-9_]` and escapes every other UTF-8 byte as `%XX`, so delimiter and Git-special bytes round-trip. Manager `Blocked by` references match complete comma-separated opaque ids without splitting punctuation. Numeric ids are unchanged. The ledger's `issue` field is a string; the loader still accepts legacy integer rows.
- 2026-08-06: Replaced the pull-request state machine, label-as-state ownership, and cost accounting. Three independent Flows coordinate through repository state, while Verdicts and checks are stored as git notes. The Builder publishes unreviewed branches; the Verifier reviews and merges them on its own clock.
